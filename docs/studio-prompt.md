# AI Studio Build 用プロンプト（mic-scope）

## 第1部：最初に貼るプロンプト

```
「マイクでオシロ」という日本語のWebアプリを作ってください。

## 何を作るか
中学・高校の理科・物理「音」の単元で、生徒が1人1台で使うオシロスコープです。スマホ・タブレット・PC のマイクで拾った音を、その場で波形として表示します。
生徒は声・口笛・楽器の音を映し、次のことを自分で確かめます。
- 音の高さ＝振動数
- 音の大きさ＝振幅
- 音色＝波形の形
一時停止して周期 T を測り、f = 1/T を自分で計算してから、アプリの値と答え合わせします。
端末は Chromebook・iPad・スマホが混在します。音は録音せず、端末の外にも送りません。

## 全体の構成
画面は4つ：スタート／スコープ（メイン）／棚・比べる／チャレンジ。
スコープ画面の下部（スマホ）または横（広い画面）に、「スコープ」「棚」「チャレンジ」のタブを置いて行き来する。

### スタート
- 使い方を3行で：「① マイクをオンにする ② 音を出して波形を見る ③ 止めて周期を測る」
- 「マイクをオンにする」ボタン。押したときに初めてマイクの許可を求める（ページを開いた時点では求めない）
- 一言：「音は録音しません。マイクの音は、この端末の中で波形にするだけで、外には送りません」
- 許可されなかったとき：「ブラウザのアドレスバーの🔒（またはカメラ・マイクの設定）から、マイクを『許可』にしてください」と表示し、もう一度試すボタンを出す
- HTTPS でないなど、マイクが使えない環境では、その理由を日本語で表示する

### スコープ画面（メイン）
- 上：波形の表示エリア（canvas）。方眼は横10目盛り×縦8目盛り。中央の横線が 0
- 波形の右（スマホでは波形の下）：「大きさ」のバー（0〜100、相対値）
- 操作バー：
  - 「一時停止／再開」の大きなボタン
  - 時間軸：1目盛りあたり 0.5 / 1 / 2 / 5 / 10 ms を「−」「＋」で切り替え。今の値を「1目盛り＝2 ms」のように表示
  - 縦の拡大：×1 / ×2 / ×5 / ×10
  - 「マイクを止める」ボタン（もう一度押すと再開）
- 一時停止中だけ使えるもの：
  - 縦のカーソル2本（A：青、B：橙）。ドラッグで左右に動かす。2本の間の時間を「T = 2.3 ms」のように小数1桁で表示
  - 「振動数を計算しよう」欄：f を数字で入力する欄（単位 Hz）と、「答え合わせ」ボタン。そばに「f = 1/T。ms を s に直すのを忘れずに」と添える
  - 「棚に置く」ボタン
- 振動数と音名の表示欄（例：「440 Hz ／ ラ（A4）＋3セント」）
  - 初期設定では隠しておく（「？？？ Hz」と表示）
  - 答え合わせをすると、その一時停止中の波形について表示する
  - 設定のスイッチ「振動数をいつも表示する」をオンにすると、再生中も常に表示する

### 答え合わせ
生徒が入力した f とアプリの推定値 f_app を比べ、カードで返す。
- 自分の値・アプリの値・ずれ（%）を並べる
- ずれ 5% 以内：「ぴったり！」
- ずれ 15% 以内：「おしい！カーソルを山の頂上にもっと正確に合わせてみよう」
- 自分の値が f_app の約1/2・1/3（ずれ 10% 以内）：「T を2周期（3周期）ぶん測っていない？ 山から『となりの』山までを測ろう」
- 自分の値が f_app の約1000倍か1/1000：「ms と s の直し方を確かめよう（1 ms = 0.001 s）」
- それ以外：「山から次の山までの時間が T だよ。もう一度測ってみよう」
- f_app が出せない波形（「—」のとき）は、「この波形は周期がはっきりしないので、答え合わせできません。声をまっすぐ伸ばしてみよう」と表示する

### 棚・比べる
- 一時停止中に「棚に置く」を押すと、名前を付けて保存する（例：「声のあ」「リコーダーのド」）。名前欄のそばに「名前や連絡先は書かない」と添える
- 棚は最大4枚。サムネイル（小さな波形）・名前・振動数・音名・大きさを表示。名前の変更・削除ができる
- 5枚目を置こうとしたら、どれを入れ替えるか選ばせる
- 2枚を選ぶと「比べる」画面へ：
  - 「重ねる」と「上下に並べる」を切り替える。1枚目は青、2枚目は橙
  - 時間軸は2枚で共通にする（どちらも、波が 0 を下から上へ横切る点を左端にそろえる）
  - 「大きさをそろえる」スイッチ：オンにすると2枚の振幅を同じに正規化して、形だけを比べられるようにする
  - 下に表：振動数／音名／周期（ms）／大きさ
  - 比べるヒントとなる問いを1つ表示し、「次の問い」で切り替える：
    - 「『あ』と『い』を同じ高さで出すと、何が違って何が同じ？」
    - 「同じ音を小さく出したときと大きく出したとき、波形のどこが変わった？」
    - 「1オクターブ上の音は、周期が何倍になった？」
    - 「リコーダーと声で同じ音名を出すと、何が同じで何が違う？」
- 「棚を空にする」ボタン（確認ダイアログつき）

### チャレンジ
お題を一覧から選んで挑戦する。挑戦中は、大きな目標表示・メーター・クリアまでの進み具合（輪のゲージ）を出す。条件を外れたら進み具合は0に戻る。クリアしたらお祝いの表示をし、一覧に✓を付ける（✓は localStorage に保存）。

1. 「ラを2秒キープ」
   - どのオクターブのラ（110・220・440・880 Hz…）でもよい。一番近いラとのずれをセントで示す、針のメーター（−50〜＋50セント）
   - ずれが ±30 セント以内を2秒続けたらクリア
2. 「1オクターブ上を出そう」
   - まず好きな高さで声を出し、「この音を基準にする」を押す（押した時点の直前0.5秒の中央値を f0 とする）
   - 目標は 2×f0。「いま 1.62 倍」のように倍率を大きく表示する
   - 2×f0 から ±40 セント以内を1.5秒続けたらクリア。クリア後に「振動数が2倍になると1オクターブ上がる」と表示する
3. 「高さはそのまま、大きさだけ変えよう」
   - 基準の音を決める（2と同じ方法で f0 と大きさ R0 を記録する）
   - 段階1：f0 から ±50 セント以内のまま、大きさを R0 の2倍以上にして1.5秒
   - 段階2：f0 から ±50 セント以内のまま、大きさを R0 の0.5倍以下にして1.5秒
   - 両方できたらクリア。クリア後に「高さ（振動数）と大きさ（振幅）は別々に変えられる」と表示する
4. 「なめらかな波を出そう」
   - 「なめらか度」（0〜100%、下の計算のきまりを参照）をメーターで示す
   - 90% 以上を2秒続けたらクリア。ヒント：「口笛や、『うー』と小さく出す声を試してみよう」

## 計算のきまり（この式と定数どおりに作ってください）
音の処理は、画面の描画から切り離した純粋な関数として dsp.ts に1つにまとめてください。定数は constants.ts にまとめ、あとで調整しやすくしてください。

### マイクの取得
- getUserMedia の audio に echoCancellation: false, noiseSuppression: false, autoGainControl: false を指定する
- AudioContext は「マイクをオンにする」ボタンを押したときに作る。iPad・iPhone のために、作ったあと resume() を呼ぶ。タブが裏から戻ったときも resume() する
- AnalyserNode（fftSize = 8192）の getFloatTimeDomainData で、最新のサンプル列（値は −1〜+1）を毎フレーム取る
- サンプリング周波数 fs は AudioContext の sampleRate をそのまま使う（端末によって 44100 か 48000）

### 波形の表示とトリガ
- 表示する時間 W = 10目盛り × 1目盛りあたりの時間。表示するサンプル数 N = W × fs
- トリガ：直近のサンプル列の中から、「0 を下から上へ横切る点」を探し、その点を画面の左端にそろえる
  - ヒステリシス：横切る前に −h 以下まで下がっていること。h = 0.1 × （その列の最大の絶対値）
  - 横切る点の候補は、その点から N サンプル分のデータが残っている範囲で、もっとも新しいものを選ぶ
  - 見つからなければ、最新の N サンプルをそのまま表示する（流れて見えてよい）
- 縦：表示エリアの上端が +1/縦の拡大率、下端が −1/縦の拡大率

### 一時停止
- 一時停止を押した瞬間に画面に出ていた N サンプルと、その直前を含む 4096 サンプルをコピーして固定する
- 一時停止中の振動数・音名・大きさは、この固定したデータから計算する（再生中の値の使い回しをしない）

### 大きさ
- RMS = √(サンプルの2乗の平均)。直近 2048 サンプルで計算する
- バーの値 = min(100, RMS / 0.3 × 100)。「dB」などの単位は表示しない

### 振動数の推定（正規化自己相関）
- 直近 4096 サンプルを x とする。τ の範囲は τmin = floor(fs/2000)〜τmax = ceil(fs/80)（およそ 80〜2000 Hz）
- r(τ) = Σ x[i]·x[i+τ] / √(Σ x[i]² · Σ x[i+τ]²)（i は 0〜4096−τmax−1 の共通の範囲で足す）
- r の最大値を rmax とする。τ を小さい方から見て、r(τ) が 0.9 × rmax を超えた最初の山（極大）を選ぶ。これで1オクターブ下（2倍の周期）を選ぶ誤りを防ぐ
- 選んだ τ の前後3点で放物線補間して、小数の τ* を出す。f = fs / τ*
- RMS < 0.01、または選んだ τ の r < 0.8 なら「—」（推定しない）とする。でたらめな数字は出さない
- 再生中の表示は、直近5回の推定の中央値を、1秒に10回だけ更新する（数字がちらつかないように）

### 音名
- n = round(12 × log2(f / 440))。MIDI 番号 m = 69 + n
- 音名（m mod 12 の順）：ド ド♯ レ レ♯ ミ ファ ファ♯ ソ ソ♯ ラ ラ♯ シ ／ 英語 C C♯ D D♯ E F F♯ G G♯ A A♯ B
- オクターブ = floor(m / 12) − 1（ラ 440Hz が A4、ド 261.6Hz が C4）
- セント = round(1200 × log2(f / (440 × 2^(n/12))))。＋は高め、−は低め
- 表示例：「ラ（A4）＋3セント」

### なめらか度（正弦波らしさ）
- 振動数 f が推定できたとき、直近 4096 サンプル x に、同じ振動数の正弦波 a·sin(2πft/fs) + b·cos(2πft/fs) + c を最小二乗であてはめる
- なめらか度 = あてはめた正弦波の成分のエネルギー ÷ （x − c）のエネルギー × 100（%）
- 正弦波なら 100% 近く、方形波なら約 81%（8/π²）になる

### 計算の確かめ（コードで自動チェックし、?debug=1 のときだけ画面の隅に結果を表示）
fs = 48000 で合成した信号を dsp.ts の関数に入れ、次を確かめる。
- 正弦波 100 / 220 / 440 / 880 / 1500 Hz：推定値の誤差が 0.5% 以内。とくに 220 と 880 で、2倍や1/2の値が出ないこと
- 方形波 200 Hz：推定値が 200 Hz（誤差 0.5% 以内）、なめらか度が 81±3%
- 正弦波 440 Hz のなめらか度が 98% 以上
- 音名：440 → ラ（A4）0セント、261.63 → ド（C4）0セント、466.16 → ラ♯（A♯4）0セント、445 → ラ（A4）＋20セント
- 振幅 0.005 の正弦波 → RMS < 0.01 なので「—」になる
- 白色雑音 → 「—」になる
さらに ?debug=1 のときは、次の実測値も表示する：
- fs
- マイクのトラックの getSettings() の echoCancellation / noiseSuppression / autoGainControl（3つとも false になっているか）
- 推定 f、選んだ τ の r、RMS、トリガの成否、なめらか度

## 見た目
- 中高生向け。波形の表示エリアは、本物のオシロスコープのような濃い背景に明るい緑の線と方眼。それ以外の画面は白い背景の落ち着いた配色
- 比べる画面の色は、1枚目＝青、2枚目＝橙で統一する。カーソル A＝青、B＝橙
- 日本語UI。用語ははじめて出るときに「周期 T（波が1回くり返すのにかかる時間）」「振動数 f（1秒間に振動する回数）」のように言いかえを添える
- 幅 360px のスマホ縦画面でも崩れないこと。波形の表示エリアは画面の上に置き、高さは最低 220px。操作はその下にまとめる
- タッチ操作が主役。カーソルのドラッグ中にページがスクロールしないようにする（canvas に touch-action: none）。カーソルはつまみやすいように、線の上下に大きめの持ち手を付ける。ボタンは指で押しやすい大きさにする
- 描画は requestAnimationFrame で行い、古い Chromebook でもカクつかないようにする

## データ
- 録音はしない。音声データをファイルにしたり、サーバーへ送ったりしない
- localStorage に保存するのは次だけ：棚の波形（最大4枚。表示していた N サンプル〔最大 4800 個、小数3桁に丸める〕・fs・1目盛りあたりの時間・名前・振動数・音名・大きさ）、設定（振動数をいつも表示するか）、チャレンジのクリア状況
- ログインなし。名前の入力欄なし
- サーバーとの通信なし

## 技術の条件
- サーバーなしで動く静的なWebアプリ（GitHub Pages で公開できること）。マイクを使うので HTTPS で公開する前提
- Gemini API など外部AIの呼び出しは入れない
- APIキーをコードに書かない
- 外部ライブラリは最小限。波形は canvas で自前で描く。音の処理は Web Audio API だけで行う
```
