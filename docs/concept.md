# マイクでオシロ（mic-scope）

## ひとことで
スマホ・タブレット・PC のマイクで拾った音を、その場で波形として映すオシロスコープ。一時停止して周期を測り、f = 1/T で振動数を出してから答え合わせをする。波形を棚に残して比べたり、お題に声で挑戦したりしながら、音の高さ・大きさ・音色を波形と結びつける。

## 利用者と場面
- 中学・高校の理科・物理「音」「波」の単元。生徒が1人1台で使う（授業中・家庭学習）
- 端末は Chromebook・iPad・スマホの混在。縦長のスマホ画面でも操作できること
- 音源は、生徒自身の声・口笛・楽器（リコーダー、音叉、鍵盤ハーモニカなど）・身の回りの音

## 学びの目的
- 音の高さ＝振動数、音の大きさ＝振幅、音色＝波形の形 だとわかる（3つは必須）
- 一時停止した波形から周期 T を読み取り、f = 1/T で振動数を計算できる
- 振動数が2倍になると1オクターブ上がることを、自分の声で確かめられる
- 誤解をほどく：「高い音＝大きい音」ではない。高さと大きさは別々に変えられる

## 体験の流れ（利用者目線）
1. **はじめる**：「マイクをオンにする」を押して、マイクの使用を許可する。「音は録音せず、端末の外にも送りません」と表示する
2. **見る**：声や楽器を鳴らすと、波形がリアルタイムで流れる。トリガで波形が止まって見えるので、形が読み取りやすい。横に「大きさ」のバー（相対値）を出す
3. **止めて測る**：「一時停止」を押して波形を固定する。2本の縦カーソルを波の山と次の山に合わせると、間の時間 T（ms）が出る。f = 1/T を自分で計算して入力する
4. **答え合わせ**：「答え合わせ」を押すと、アプリが推定した振動数（Hz）と音名（例：ラ／A4 ＋12セント）が出て、自分の計算と並べて表示される。Hz と音名は、最初は隠しておく（設定で常に表示にもできる）
5. **棚に置いて比べる**：止めた波形に名前を付けて（例：「声のあ」「リコーダーのド」）、棚に最大4枚まで置く。2枚を選んで重ねたり上下に並べたりして、高さ（周期）・大きさ（振幅）・形の違いを比べる。比べるときのヒントとなる問い（例：「『あ』と『い』では、何が違って何が同じ？」）を添える
6. **お題チャレンジ**：お題を選んで声や楽器で挑戦する。条件を一定時間保てたらクリア
   - 「ラ（440Hz）を2秒キープ」：音名と、ずれの大きさを示すメーターで導く
   - 「さっきの音の1オクターブ上を出そう」：直前の音の2倍の振動数を目標にする
   - 「高さはそのままで、大きさだけ変えよう」：振動数を保ったまま、大きさのバーを上げ下げする
   - 「なめらかな波を出そう」：口笛などで、正弦波に近い形を目指す

## 画面一覧
- **スタート**：使い方3行、マイクの許可ボタン、プライバシーの一言
- **スコープ画面（メイン）**：上に波形（方眼つき）、横に大きさのバー、下に操作（一時停止／時間軸の拡大縮小／縦の拡大縮小／カーソル）と、Hz・音名の表示欄（初期は隠す）、f の入力欄と答え合わせボタン
- **棚**：保存した波形のサムネイル（最大4枚）、名前の編集、削除、重ねる／並べる の切り替え
- **比べる画面**：選んだ2枚を重ねる／上下に並べる。それぞれの Hz・音名・大きさを表に並べる
- **チャレンジ**：お題の一覧と、挑戦中の画面（目標・メーター・残り時間）

## 計算と表示のきまり（試作で崩れやすい所）
- マイクの取得では、エコー除去・ノイズ除去・自動音量調整（echoCancellation / noiseSuppression / autoGainControl）をすべて切る
- サンプリング周波数は端末まかせ（多くは48kHz）。実際の値を `?debug=1` の画面に出す
- トリガ：上向きにゼロを横切った点（ヒステリシスつき）を画面の左端にそろえる。そろわないときはそのまま流す
- 振動数の推定：自己相関で基本周波数を求める。対象はおよそ 80〜2000Hz。音が小さいときや、はっきりした周期がないときは「—」と表示する（でたらめな数字を出さない）
- 音名：A4 = 440Hz を基準に、n = 12·log2(f/440) を四捨五入して音名を決め、ずれをセント（100セント＝半音）で示す。表記は「ラ／A4 ＋12セント」のように日本語と英語を併記する
- 大きさ：RMS を相対値のバーで示す。「何dB」とは表示しない（端末ごとに校正されていないため）
- 時間軸：1目盛りあたり 0.5 / 1 / 2 / 5 / 10 msを切り替えられる。カーソルの時間差は ms で小数1桁まで表示する
- `?debug=1` で、サンプリング周波数・推定 Hz・自己相関の強さ・トリガの成否を数値で表示する

## データと公開範囲（保存の有無・ログインの有無・個人情報）
- 音声は録音しない。マイクの音は端末の中で処理するだけで、サーバーには送らない
- 保存：棚の波形（数十ミリ秒ぶんの数値と、名前・Hz・大きさ）と設定だけを、その端末の localStorage に保存する。Firebase は使わない
- ログイン：なし。名前の入力欄も置かない
- 個人情報：棚の名前欄に「名前や連絡先は書かない」と添える
- 「棚を空にする」ボタンを置く
- 一般公開（URL を配るだけで使える）。マイクを使うので HTTPS で公開する

## 試作で確かめたいこと（AI Studio Build で見たい点）
- iPad の Safari・Chromebook・Android スマホで、マイクの許可から波形の表示まで通るか（ボタンを押してから許可を求める流れになっているか）
- 音声処理を切った状態で、声を一定に出したときに波形の大きさが勝手に変わらないか
- トリガで波形が止まって見えるか。声のように揺れる音でも読み取れるか
- 音叉や鍵盤の既知の音（例：ラ 440Hz）で、推定 Hz と音名が合うか。オクターブ違い（220Hz や 880Hz と出る）を起こさないか
- 一時停止した瞬間の波形が、その直前に見えていた波形と同じか
- カーソルで測った T から出した f と、アプリの推定 Hz がおおむね一致するか
- 棚に保存した波形を、再読み込みしたあとも重ねて比べられるか
- お題チャレンジのメーターが、揺れすぎず遅すぎず、声で合わせられる反応になっているか
- 縦長のスマホ画面で、波形・操作・入力欄を無理なく行き来できるか

## やらないこと
- 録音・再生・音声ファイルの保存や書き出し
- 基準音（正弦波など）をアプリから鳴らす機能（1台で鳴らしながら拾うとハウリングや回り込みが起きやすいため）
- 周波数スペクトル（FFT）の表示（今回は波形と時間に集中する）
- dB や電圧などの絶対値の表示
- 教師による集計・クラス全体への共有

## 反映した教訓
- 主役を最初に1つに決める → 生徒1人1台のソロ利用に絞った（2026-10-02 lemonade-game-v2）
- 計算は式と定数のまま書く／`?debug=1` で数値を確かめられるようにする → 「計算と表示のきまり」にまとめた（2026-10-19 coaster-mission、2026-11-16 teizaiha-lab）
- 「〜した瞬間に〜する」条件は守られにくい → 一時停止の瞬間の波形やトリガのそろい方を「確かめたいこと」に入れた（2026-10-19 coaster-mission）
- 表示の揺れは AI Studio で深追いしない → トリガとメーターの反応は、取り込み後に `/build` で詰める前提にした（2026-10-19 coaster-mission）
- 「考えなくても勝てる」状態を避ける → Hz を最初は隠し、自分で f = 1/T を計算してから答え合わせにした（2026-10-02 lemonade-game-v2）
- 取り込み後は、最初に「生徒が1人で使う」通しのテストをする（2026-10-20 coaster-mission）
